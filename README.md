# 業務マニュアル作成アシスタント

質問に答えていくだけで、業務マニュアルができあがり、DocBase に投稿されます。
文章を書くのも、DocBase に貼り付けるのも、こちらでやります。
必要な操作は **`/new`（新しく作る）** と **`/edit`（直す）** の2つだけです。

---

## 1. 初回セットアップ（最初の1回だけ）

### ステップ1：Claude Code を入れる

公式の手順に沿ってインストールしてください。
👉 https://docs.claude.com/ja/docs/claude-code/setup

### ステップ2：このフォルダをパソコンに取り込む

**A. GitHub Desktop を使う場合（おすすめ・かんたん）**

1. GitHub Desktop を開く（未インストールなら https://desktop.github.com/ から入れる）
2. メニューの `File` → `Clone repository`
3. `URL` タブを選び、このリポジトリの URL を貼り付ける
4. `Local path`（保存先）を確認して `Clone` をクリック

**B. ターミナルを使う場合**

```bash
git clone <このリポジトリのURL>
```

取り込んだあと、`cd`（clone したフォルダ）でそのフォルダに移動します。

### ステップ3：フォルダを開いて起動する

取り込んだ `docbase-manual-agent` フォルダで、ターミナルを開いて次を入力します。
（GitHub Desktop なら `Repository` → `Open in Terminal` で開けます）

```bash
claude
```

### ステップ4：DocBase につなぐ

1. 起動した画面で `/mcp` と入力して Enter
2. 一覧から `docbase-mcp` を選ぶ
3. `Authenticate` を選ぶ
4. ブラウザが開くので、いつもの DocBase にログインして「許可」を押す
5. **`Authentication successful`** と表示されれば完了です

> 「このMCPサーバーを信頼しますか」といった確認が出たら、`Yes` を選んでください。

これでセットアップは終わりです。次回からは `claude` と入力するだけで使えます。

---

## 2. 使い方

### 新しいマニュアルを作る

```
/new
```

「どんな業務のマニュアルを作りますか？」と聞かれるので、答えていくだけです。
質問は1〜2個ずつ来ます。分からない項目は「分かりません」で大丈夫です（あとで埋められます）。

途中で「ここまでの内容」がまとめて表示されるので、違っていたらその場で言ってください。

最後に**投稿内容の全文**が表示されます。よければ「はい」と答えると DocBase に投稿されます。
直したいところがあれば、そのまま言ってください。何度でも直せます。

### 既存のマニュアルを直す

```
/edit
```

「どのマニュアルを修正しますか？」と聞かれるので、タイトルの一部やキーワードを答えてください。
候補が出てくるので選ぶと、いまの内容が表示されます。

「〇〇の部分を△△に変えたい」のように伝えると、**変更前と変更後**を並べて見せてくれます。
最後に全文を確認して「はい」と答えると、DocBase が更新されます。

### 途中でやめたいとき

**「やめます」** と入力してください。
そこまでの内容は下書きとして保存され、DocBase には何も投稿されません。あとで続きから再開できます。

### 終わるとき

`/exit` と入力するか、`Ctrl` + `C` を2回押します。

---

## 3. 注意事項

- **削除はこのツールではできません。**
  マニュアルを消したいときは、DocBase の画面から操作してください（誤って消さないための安全策です）。

- **画像・スクリーンショットはあとから追加します。**
  このツールは文章だけを作ります。画像を入れたい場合は、投稿したあとに DocBase の画面で編集して追加してください。

- **投稿前に必ず全文が表示されます。**
  「はい」と答えるまで、DocBase には何も書き込まれません。安心して進めてください。

- **他の人が同時に編集していたら、更新を止めます。**
  `/edit` の途中で他のメンバーが DocBase 側を編集していた場合、上書きせずにいったん止めて、
  最新の内容を出し直します。そのままやり直してください。

## 4. 困ったときは

| 症状 | 対処 |
|---|---|
| 「DocBase につながらない」と言われる | `/mcp` と入力 → `docbase-mcp` → `Authenticate` で再度ログインしてください（認証は時間が経つと切れます） |
| `/new` や `/edit` が反応しない | いま開いているフォルダが `docbase-manual-agent` になっているか確認してください。違う場所で `claude` を起動していると使えません |
| `/mcp` に `docbase-mcp` が出てこない | 同上。フォルダの場所を確認してください |
| 途中で画面が固まった / 応答が止まった | `Ctrl` + `C` を1回押すと中断できます。`claude` を起動し直しても、下書きは `drafts` フォルダに残っています |
| 間違って投稿してしまった | DocBase の画面から直接修正するか、`/edit` で直してください |
| 前回の下書きを続きから書きたい | `drafts` フォルダの中身を見て、「〇〇の下書きの続きをやりたい」と伝えてください |
| 「許可しますか？」という確認が出た | 投稿・更新のときに出ます。内容を確認して問題なければ許可してください |

それでも解決しないときは、このリポジトリの管理者に連絡してください。

## 5. （管理者向け）チーム設定の変更

既定値は **`config/docbase.yaml` が唯一の置き場所**です。実際の値はそのファイルを開いて確認・変更してください
（このファイルには値を書き写しません。二重管理になり、食い違いのもとになるためです）。

設定できる項目は次の6つです。用途は yaml 内のコメントに書いてあります。

| キー | 用途 |
|---|---|
| `defaults.tags` | 常に付けるタグ |
| `defaults.scope` | 公開範囲（`everyone` / `group` / `private`） |
| `defaults.group_name` | `scope` が `group` のときのグループ名 |
| `defaults.draft` | `true` なら DocBase の下書きとして投稿 |
| `defaults.title_prefix` | タイトルの先頭に付ける文字列（`""` なら付けない） |
| `defaults.notice` | 更新時にメンバーへ通知するか |

マニュアルの見出し構成は `templates/manual-template.md`、
アシスタントの振る舞いは `CLAUDE.md` と `.claude/commands/` にあります。

### MCP ツール名について

`.claude/settings.json` の権限設定は、DocBase MCP のツール名が
`searchPosts` / `getPost` / `createPost` / `updatePost` / `patchPostBody` / `getTags` / `searchGroups`
であることを前提にしています。
DocBase 側の仕様変更でツール名が変わった場合は、`/mcp` → `docbase-mcp` → `View tools` で実名を確認し、
`.claude/settings.json` の `mcp__docbase-mcp__<ツール名>` を書き換えてください。
